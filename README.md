# PICKS — 開発引き継ぎ資料 (2026年7月時点)

KEYS (lifelonglearning777.github.io/keys/) の姉妹アプリ。
「今おぼえたい表現」だけを集めた期間限定セットを、数か月ごとに追加していく単一ファイルWebアプリ。
中2英語・定期テスト対策用。生徒が実際にテスト勉強に使うため、**データの正確さ最優先**。

新しいチャットでこの続きをやるときは、この資料と `index.html` を渡して
「このREADMEを読んで、〜をやってください」と伝えればOK。

## 公開方法
1. GitHubでリポジトリ(例: `picks`)を作成
2. `index.html` をドラッグ&ドロップでアップロード
3. Settings > Pages で公開 → `lifelonglearning777.github.io/picks/`
更新は index.html の差し替えのみ。完全クライアントサイド(サーバー・AI不使用)。

## デザイン言語(最重要・ここを外すと後戻りする)

### 配色方針
Linear/Raycast/Vercel系の「ダークテーマ+アクセント1色を絞ったUI」を目指している。
```
背景      : var(--table)     #0F172A (ダークネイビー)
メイン色   : var(--gold)      #14B8A6 (ターコイズ) ← アプリの唯一のメインアクセント
メイン色(明): var(--gold-2)    #2DD4BF
特別演出色 : var(--amber)     #FBBF24 (ゴールド/琥珀) ← MASTER達成・宝箱の中身だけに使う
エラー     : var(--red)       #FF4D3D
文字       : var(--on)        #F1F5F9 (ほぼ白)
```
**重要な原則**:
- `--gold`という変数名だが、中身はターコイズ。名前と実体がズレているので、色を触るときは
  変数名でなく実際の値を確認すること。
- **青(`--blue` #2E6BFF)は「タイピング」モードを示す色としてのみ意図的に残している**
  (ホーム画面の3ボタン: タイピング=青、英作文=赤、CBT=ターコイズ、と3モードを色分けするため)。
  それ以外の場所(ボタン、フォーカス枠、進捗バー、ホバー色など)に青が残っていたら、それは
  **直し忘れ・バグ**である可能性が高い。これまで青の塗り残しを何度も見つけて直してきた
  (CBT画面のボタン、input focus枠、ミッション進捗バー、記録ページの棒グラフなど)。
  新しい画面を作る/触るときは、青が紛れ込んでいないか必ず確認する。
- **amber(琥珀)は「特別な瞬間」専用**。宝箱の中の宝物・MASTER達成カードなど、
  ここぞという場面にだけ使う。ボタンや通常UIには使わない(ターコイズと差をつけるのが目的)。
- 宝箱そのものは意図的に暖色(茶色・金)のまま。ターコイズで縁取ると寒色・暖色がぶつかって
  かえって雑然とするのでNG(この方針は確認済み)。

### 避けるべきデザイン(「素人っぽい」と繰り返し指摘された要素)
- **斜め回転したハンコ風スタンプ**(`transform:rotate(-Ndeg)` + 太い枠線) は絶対NG。
  何度も別の場所に紛れ込んでいたので、新しく「達成」「完了」系の表示を作るときは
  このパターンを踏襲しないこと。代わりに: 小さいドット(●)+テキストのピル型バッジ
  (`.stamp`, `.md-stamp`, `.reward .r-stamp` などを参照)。
- **横長のピル型バッジを並べすぎる**(統計情報を全部pill化すると「教材っぽく」なる)。
  文字情報は「・」区切りのシンプルな一行テキストにする方が洗練される
  (`.type-stats` を参照)。
- **明るい紙面カード(白/クリーム)がダーク画面に唐突に浮く**のもNG。
  今回「今日の宝箱」カードをダーク化して解決した(`.chest-card`)。
  **ただしタイピング/ステップ/語順/英作文/CBTの各セッション画面(`.sheet`本体)は
  まだ明るい紙面のまま、意図的に変えていない**(視認性重視で保留中。ここを今後
  ダーク化するかどうかは要相談)。
- **情報の重複**: 同じ情報を2箇所に出さない。例:「鍵を獲得した」通知カードは廃止し、
  右上の鍵アイコン(`.key-progress`)が大きくポップするアニメーションだけで表現している。
  セッション完了画面の「今日の合計/鍵/マスター」も、**累計**(ヘッダーに常時表示済み)
  ではなく、**そのセッションで増えた分だけ**(`keysGained`/`masterGained`)を出すように
  変更済み。新しい通知UIを作るときは「これは他の場所と重複していないか」を必ず確認する。
- **説明文の改行位置**: ポップオーバー(`.info-pop`)内で太字ラベルは`display:block`にして
  必ず独立行にする。長い説明は自然な意味の切れ目で`<br>`を入れ、単語の途中や
  「〜という」のような助詞の直前で折り返らないよう注意する。

### UIパターン集
- **「?」情報ポップオーバー**(`.info-pop` / `.info-pop-panel`): 常時表示だと文字が
  多すぎる説明は、この丸い「?」アイコンの中に格納する。見出し行の中に**自然な
  flexの流れ**で置く(`class="info-pop inline"`)。絶対配置(`position:absolute`)で
  浮かせると、コンテナによって位置がずれて他の要素と重なるバグの元になるので注意
  (実際に何度か位置ズレが起きて直した)。
- **鍵システム**: 各問題は「お手本」「ステップ」「語順」「英作文」の4モードで練習でき、
  鍵(c/m/w)を集めると3本でその文が「マスター」になる。
  - お手本: 鍵1本(表示通り完全一致が必要、ゆるさなし)
  - ステップ: 鍵3本(4段階を経て最後は日本語だけで書くので、まとめて3本)
  - 語順: 鍵2本(表示された1つの語順に固定)
  - 英作文: 鍵1本(ヒントなしのときのみ)
  - 文を直接タップすると常に「ステップ」が始まる。
  設定画面の「採点のルール」に、この仕組みと採点基準の詳しい説明あり
  (`function vSettings`内、LEARNINGセクション)。
- **鍵の獲得演出**: 問題右上の`.key-progress`アイコンが大きくポップ+発光する
  (`.key-progress i.pop`)。MASTER達成時だけ`.key-earn.master`のコンパクトな
  お祝いカードが出る(amber色)。
- **オンスクリーンキーボード**(お手本モードのみ): `kbHtml()`関数。次に押すキーを
  ハイライトする。日本語(JIS)キーボード配列に合わせて、アポストロフィは
  「7」+Shiftをハイライトする(US配列の独立キーではない)。数字行は装飾のみ(押せない、
  常時グレー)で、実物のキーボードとの位置対応をわかりやすくするために表示している。

## 採点エンジンの仕様(judge関数, `function judge`)
- **短縮形**(I'm/I am、don't/do not等)は**全モードで**どちらでも正解(`CONTR`配列)。
- **同義語**(bicycle/bike等)も全モードで正解(`SYN`配列)。
- **that節の省略**は`writeAlt`フィールドで管理。**英作文・CBTのみ**で有効
  (お手本・ステップ・語順では表示通りの形が必要)。実装は`judge()`呼び出し時に
  `{...q,answers:[...q.answers,...q.writeAlt]}`を一時的に作って渡す(bindWrite/submitCbtを参照)。
- **if(when)節の語順**・**give/buy/sendの書きかえ**(dative alternation)は`alt`フィールドで
  管理。**お手本・語順は表示された1つの語順に固定**(judge()を呼ばず、q.enとの完全一致
  チェックのみのため)。**ステップ・英作文・CBTでは正解**(judge()がq.answers全体を見るため)。
  - because節は今のところ後ろ置きのみ正解(前置きは意図的に未対応)。
- **大文字・記号の厳しさ**: 英作文モードのみ`S.set.strictCase`で調整可(初期値ゆるめ)。
  CBTは常に厳格。お手本・語順・ステップはこの設定と無関係(それぞれ独自のロジック)。
- ヒント(`ヒントを許可`設定)は5段階: 文の型→語数→頭文字→シャッフルされた単語カード→全文。

## 品質管理でやったこと(同じミスを繰り返さないために)
- 155問全件を機械的にエクスポートして、大文字始まり・終端記号・疑問符整合性などを
  スクリプトでチェック済み(日付は2026年7月時点)。
- 同じ日本語プロンプトに違う英語が対応する重複が過去に1件見つかった(if節)ので、
  新しいシーズンを追加するときは重複日本語がないかチェックすると安心
  (`Q.find`/`groupby`的なスクリプトで簡単に確認できる)。
- SVGアイコンで「意図した形と違うものが描画されている」バグが複数個所(鍵のはずが
  虫眼鏡に見える等)で見つかった。同じ間違ったコードが**複数箇所にコピペされていて
  1箇所直しても直っていなかった**ことがあったので、同種のアイコンは全箇所を
  `grep`で洗い出してから直すこと。

## よくある追加・変更
- **表現を足す**: 該当ユニットの`items`に`{ja:"...",en:"...",pat:"...",exp:"..."}`を追加
  (別解は`alt:["..."]`、英作文限定の別解は`writeAlt:["..."]`)。
- **新しいシーズンを追加**: `DATA`配列の最後に`{name,sub,grade,units:[...]}`を追加するだけ。
  `name`はホーム画面の見出しになるので「2年後期中間」のように学年+テスト名で短く。
  ユニット分けは、テストの出題形式(並べかえ/書きかえ等)ではなく**文法・意味のまとまり**で。
  まとめられないものは「その他の重要表現」ユニットへ。
